# Deployment Flutter ke Production

## Pengantar

Menulis kode Flutter adalah setengah perjalanan. Setengah lainnya adalah mengantarkan aplikasi ke pengguna. Deployment mencakup build signing, store submission, app flavors untuk environment berbeda, CI/CD automation, dan pre-deployment checklist. Satu kesalahan di tahap ini bisa menunda rilis berhari-hari.

Tutorial ini membahas end-to-end deployment Flutter: dari konfigurasi signing lokal hingga CI/CD pipeline yang otomatis build dan deploy ke Play Store dan App Store.

## Android Deployment

### 1. Generate Keystore

Android membutuhkan keystore (file .jks/.keystore) untuk menandatangani APK/AAB. Tanda tangan ini memverifikasi identitas developer.

```bash
# Generate keystore (sekali saja)
keytool -genkey -v \
  -keystore ~/upload-keystore.jks \
  -keyalg RSA \
  -keysize 2048 \
  -validity 10000 \
  -alias upload
```

**Isi prompt keytool:**
- Password keystore (simpan aman-amannya)
- Konfirmasi password
- Nama depan & belakang (nama developer/company)
- Unit organisasi
- Nama organisasi
- Kota, provinsi, kode negara
- Konfirmasi

**PENTING:** Simpan keystore file dan password di tempat aman, bukan di repository.

### 2. Konfigurasi key.properties

```properties
# android/key.properties — JANGAN di-commit ke git!
storePassword=your_keystore_password
keyPassword=your_key_password
keyAlias=upload
storeFile=/Users/you/path/to/upload-keystore.jks
```

**Security:** File ini berisi credential. Tambahkan ke `.gitignore`:

```gitignore
# .gitignore
android/key.properties
*.jks
*.keystore
```

Untuk CI/CD, gunakan environment variables atau secret store (GitHub Secrets, Codemagic Environment Variables).

### 3. Signing Config di build.gradle

```gradle
// android/app/build.gradle
def keystoreProperties = new Properties()

// Baca key.properties (local development)
def keystorePropertiesFile = rootProject.file('key.properties')
if (keystorePropertiesFile.exists()) {
    keystoreProperties.load(new FileInputStream(keystorePropertiesFile))
}

android {
    // ... konfigurasi lain

    defaultConfig {
        applicationId "com.yourcompany.yourapp"
        minSdkVersion 21
        targetSdkVersion 34
        versionCode flutterVersionCode.toInteger()
        versionName flutterVersionName
    }

    // Konfigurasi signing
    signingConfigs {
        release {
            keyAlias keystoreProperties['keyAlias']
            keyPassword keystoreProperties['keyPassword']
            storeFile keystoreProperties['storeFile'] ?
                file(keystoreProperties['storeFile']) : null
            storePassword keystoreProperties['storePassword']
        }
    }

    buildTypes {
        release {
            signingConfig signingConfigs.release

            // Obfuscation & minification
            // Requires dart code obfuscation in pubspec.yaml
            // flutter build appbundle --obfuscate --split-debug-info=build/debug-info

            // ProGuard (untuk Android native code)
            minifyEnabled true
            proguardFiles getDefaultProguardFile('proguard-android-optimize.txt'), 'proguard-rules.pro'
        }
    }
}
```

### 4. App Signing by Google Play

Google merekomendasikan **App Signing by Google Play**. Flow-nya:

1. Upload signing key (keystore) untuk app signing
2. **Upload key** (key yang Anda buat) — digunakan untuk mengupload build ke Play Console
3. **App signing key** — digunakan Google Play untuk menandatangani AAB yang didistribusikan ke pengguna

**Keuntungan App Signing by Google Play:**
- Jika upload key hilang/kompromi, Google bisa reset tanpa perlu ubah package name
- Google manage app signing key distribution
- Support untuk split APKs dan install APK expansion

**Setup:**
1. Di Play Console: Release > Setup > App Integrity
2. Pilih "Let Google manage your app signing key" (atau upload existing key)
3. Register upload key certificate

### 5. Build Android App Bundle (.aab)

```bash
# Development build (debug)
flutter build apk --debug

# Release build (APK — untuk testing manual)
flutter build apk --release

# Release build (App Bundle — untuk Play Store)
flutter build appbundle --release

# Dengan obfuscation (recommended untuk production)
flutter build appbundle \
  --release \
  --obfuscate \
  --split-debug-info=build/debug-info

# Dengan target platform
flutter build appbundle --release --target-platform android-arm,android-arm64,android-x64
```

**APK vs AAB:**

| Format | Ukuran | Distribusi | Use Case |
|--------|--------|------------|----------|
| APK | Besar ($\sim$50MB) | Manual/sideload | Testing internal |
| AAB | Kecil ($\sim$30MB base) | Play Store | Production |
| Split APK | Per-config ($\sim$15MB) | Google Play | Optimized delivery |

Google Play mementukan AAB mulai Agustus 2023 untuk aplikasi baru. AAB memungkinkan **app bundle delivery** — pengguna hanya mendownload asset yang sesuai dengan device mereka.

### 7. Upload ke Google Play Console

**Langkah-langkah:**
1. Buka [Google Play Console](https://play.google.com/console)
2. Create app (jika belum)
3. Isi store listing: description, screenshots, category, content rating
4. Production > Release > Create new release
5. Upload AAB file (hasil `flutter build appbundle --release`)
6. Isi "What's new in this release" (release notes)
7. Review dan rollout

**Tracks:**

| Track | Tujuan | Coverage | Durasi Review |
|-------|--------|---------|---------------|
| **Internal Testing** | Developer & QA team | 100 user emails | Instant |
| **Closed Testing** (Alpha) | Beta testers, friends | Up to 100 testers | Beberapa jam |
| **Open Testing** (Beta) | Public beta | Unlimited | Beberapa jam |
| **Production** | All users | 100% | Beberapa jam - 2 hari |

**Best practice:** Mulai dari Internal Testing, lalu Alpha, lalu Production. Jangan langsung production — risiko regression.

### Update Versi Setelah Release

Jika ada bug setelah rilis production, Anda harus:
1. Increment version code (build number) di pubspec.yaml
2. Build ulang
3. Upload sebagai **new release** dengan version code yang lebih tinggi
4. Google Play tidak mengizinkan upload AAB dengan version code yang sudah ada

```yaml
# pubspec.yaml
version: 1.0.0+1   # 1.0.0 = versionName, +1 = versionCode
```

Setelah rilis pertama: `1.0.0+1`
Bug fix: `1.0.1+2`
Fitur baru: `1.1.0+3`

## iOS Deployment

### 1. Apple Developer Program ($99/tahun)

Bergabung dengan Apple Developer Program:
1. Buka [developer.apple.com](https://developer.apple.com)
2. Enroll dengan Apple ID
3. Bayar $99 USD per tahun (auto-renew)

Tanpa membership, Anda tidak bisa:
- Build untuk distribution (Archive)
- Upload ke App Store Connect
- TestFlight (external testers)
- Push notification
- In-app purchase

### 2. Xcode Certificate dan Provisioning Profile

```bash
# Buka Xcode project
open ios/Runner.xcworkspace
```

**Certificate types (Signing & Capabilities > All > Certificate):**
- **Development certificate**: Digunakan saat develop di device (debug)
- **Distribution certificate**: Digunakan saat build untuk App Store (App Store Connect) atau ad-hoc distribution

**Provisioning profiles:**
- Menghubungkan certificate + App ID + device (untuk development)
- Xcode manage secara otomatis dengan **Automatically manage signing**

**Setting signing di Xcode:**
1. Buka `ios/Runner.xcworkspace` di Xcode
2. Pilih target Runner > Signing & Capabilities
3. Centang "Automatically manage signing"
4. Pilih team (Apple Developer account)
5. Xcode akan generate certificate dan provisioning profile secara otomatis

**Bundle identifier** harus unik dan konsisten dengan App Store Connect:
```
com.yourcompany.yourapp
```

### 3. Build dan Archive

```bash
# Bersihkan build cache (sering diperlukan untuk menghindari error aneh)
flutter clean
cd ios && pod deintegrate && pod install --repo-update && cd ..

# Build untuk iOS (debug — testing di simulator)
flutter run

# Build untuk release (archive)
flutter build ios --release --no-codesign

# Archive via Xcode
# Buka ios/Runner.xcworkspace di Xcode
# Product > Archive
```

**Jika error "No matching provisioning profiles":**
1. Buka Xcode
2. Preferences > Accounts > Download Manual Profiles
3. Atau hapus provisioning profiles lama di `~/Library/MobileDevice/Provisioning Profiles/`

### 4. App Store Connect

Setelah archive berhasil, Xcode akan membuka organizer:

1. Pilih archive terbaru
2. Click **Distribute App**
3. Pilih **App Store Connect** (distribution method)
4. Pilih **Upload** (kirim ke App Store Connect)
5. Pilih signing yang sesuai
6. Setelah upload, buka [App Store Connect](https://appstoreconnect.apple.com)

**App Store Connect tasks:**
- **App Information**: Nama app, bundle ID, SKU, primary language
- **Pricing**: Price tier, availability (paid/free), in-app purchases
- **App Review Information**: Contact info, demo account jika perlu login
- **Build**: Pilih build yang sudah di-upload dari Xcode
- **App Privacy**: Privacy policy URL, data collection disclosure
- **Version Release**: Manual release atau auto release after review

### 5. TestFlight

TestFlight adalah platform beta testing Apple:

```bash
# Setelah upload build ke App Store Connect:
# 1. Buka TestFlight tab di App Store Connect
# 2. Build akan "Processing" (butuh ~30 menit)
# 3. Setelah selesai, enable untuk testing
```

**Internal Testers:**
- Hingga 100 members dari App Store Connect team
- Tidak perlu review dari Apple
- Langsung bisa install via TestFlight app

**External Testers:**
- Hingga 10.000 testers
- Butuh **Beta App Review** dari Apple (1-2 hari)
- Link undangan bisa dishare ke publik

```dart
// opsional: Tampilkan dialog untuk join TestFlight
import 'package:url_launcher/url_launcher.dart';

Future<void> openTestFlight(String appStoreId) async {
  final testflightUrl = 'itms-beta://testflight.apple.com/join/$appStoreId';
  final canOpen = await canLaunchUrl(Uri.parse(testflightUrl));

  if (canOpen) {
    await launchUrl(Uri.parse(testflightUrl));
  }
}
```

## App Flavors

App flavors memungkinkan Anda memiliki **multiple environment (dev, staging, prod)** dalam satu codebase.

### Setup Flavor di Flutter

```bash
# Run dengan flavor tertentu
flutter run --flavor dev -t lib/main_dev.dart
flutter run --flavor staging -t lib/main_staging.dart
flutter run --flavor prod -t lib/main.dart

# Build dengan flavor
flutter build appbundle --flavor dev -t lib/main_dev.dart
flutter build ios --flavor dev -t lib/main_dev.dart --no-codesign
```

### Entry Points

```dart
// lib/main_dev.dart
import 'package:flutter/material.dart';
import 'app.dart';

void main() {
  // Konfigurasi development environment
  FlavorConfig(
    appName: 'MyApp Dev',
    baseUrl: 'https://dev.api.example.com',
    isProduction: false,
    enableLogging: true,
  );

  runApp(const MyApp());
}
```

```dart
// lib/main_staging.dart
import 'package:flutter/material.dart';
import 'app.dart';

void main() {
  FlavorConfig(
    appName: 'MyApp Staging',
    baseUrl: 'https://staging.api.example.com',
    isProduction: false,
    enableLogging: true,
  );

  runApp(const MyApp());
}
```

```dart
// lib/main.dart
import 'package:flutter/material.dart';
import 'app.dart';

void main() {

```

### Flavor Configuration Class

```dart
// lib/core/config/flavor_config.dart
class FlavorConfig {
  static late final FlavorConfig instance;

  final String appName;
  final String baseUrl;
  final bool isProduction;
  final bool enableLogging;

  FlavorConfig._({
    required this.appName,
    required this.baseUrl,
    required this.isProduction,
    required this.enableLogging,
  });

  factory FlavorConfig({
    required String appName,
    required String baseUrl,
    required bool isProduction,
    required bool enableLogging,
  }) {
    instance = FlavorConfig._(
      appName: appName,
      baseUrl: baseUrl,
      isProduction: isProduction,
      enableLogging: enableLogging,
    );
    return instance;
  }
}
```

### Android Flavor Config

```gradle
// android/app/build.gradle
android {
    // ... konfigurasi default

    flavorDimensions "environment"
    productFlavors {
        dev {
            dimension "environment"
            applicationIdSuffix ".dev"

        }

            dimension "environment"

        prod {
            dimension "environment"
            applicationIdSuffix ""
            versionNameSuffix ""
            resValue "string", "app_name", "MyApp"
        }
    }

    sourceSets {
        // Source set untuk setiap flavor
        dev {
            manifest.srcFile 'src/dev/AndroidManifest.xml'
        }
        staging {
            manifest.srcFile 'src/staging/AndroidManifest.xml'
        }
        prod {
            manifest.srcFile 'src/prod/AndroidManifest.xml'
        }
    }
}
```

### iOS Flavor Config

Di Xcode:
1. Duplicate target Runner menjadi:
   - Runner Dev
   - Runner Staging
   - Runner (production)
2. Set bundle identifier untuk masing-masing:
   - `com.yourcompany.yourapp.dev`
   - `com.yourcompany.yourapp.staging`
   - `com.yourcompany.yourapp`
3. Set Product Bundle Name (app name yang tampil di Home screen)
4. Buat scheme baru untuk setiap flavor

Atau gunakan package [flutter_flavorizr](https://pub.dev/packages/flutter_flavorizr) untuk mengotomatiskan setup flavor.

## CI/CD dengan GitHub Actions

### Flutter CI Pipeline

```yaml
# .github/workflows/flutter-ci.yml
name: Flutter CI/CD

on:
  push:
    branches: [main, develop]
  pull_request:
    branches: [main]

jobs:
  analyze:
    name: Analyze
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4

      - uses: subosito/flutter-action@v2
        with:
          flutter-version: '3.16.x'
          channel: 'stable'

      - name: Install dependencies
        run: flutter pub get

      - name: Analyze
        run: flutter analyze

  test:
    name: Test
    needs: analyze
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4

      - uses: subosito/flutter-action@v2
        with:
          flutter-version: '3.16.x'
          channel: 'stable'

      - name: Install dependencies
        run: flutter pub get

      - name: Run unit & widget tests
        run: flutter test --coverage

      - name: Upload coverage
        uses: actions/upload-artifact@v4
        with:
          name: coverage-report
          path: coverage/lcov.info

  build-android:
    name: Build Android
    needs: test
    runs-on: ubuntu-latest

    steps:
      - uses: actions/checkout@v4

      - uses: subosito/flutter-action@v2
        with:
          flutter-version: '3.16.x'
          channel: 'stable'

      - name: Install dependencies
        run: flutter pub get

      - name: Setup Android keystore
        env:
          KEYSTORE_BASE64: ${{ secrets.KEYSTORE_BASE64 }}
          KEYSTORE_PASSWORD: ${{ secrets.KEYSTORE_PASSWORD }}
          KEY_PASSWORD: ${{ secrets.KEY_PASSWORD }}
          KEY_ALIAS: ${{ secrets.KEY_ALIAS }}
        run: |
          echo "$KEYSTORE_BASE64" | base64 --decode > android/app/upload-keystore.jks
          echo "storePassword=$KEYSTORE_PASSWORD" >> android/key.properties
          echo "keyPassword=$KEY_PASSWORD" >> android/key.properties
          echo "keyAlias=$KEY_ALIAS" >> android/key.properties
          echo "storeFile=upload-keystore.jks" >> android/key.properties

      - name: Build AAB
        run: |
          flutter build appbundle --release \
            --obfuscate \
            --split-debug-info=build/debug-info

      - name: Upload AAB
        uses: actions/upload-artifact@v4
        with:
          name: app-release.aab
          path: build/app/outputs/bundle/release/app-release.aab

  build-ios:
    name: Build iOS
    needs: test
    runs-on: macos-latest

    steps:
      - uses: actions/checkout@v4

      - uses: subosito/flutter-action@v2
        with:
          flutter-version: '3.16.x'
          channel: 'stable'

      - name: Install dependencies
        run: flutter pub get

      - name: Install CocoaPods
        run: |
          cd ios
          pod install --repo-update

      - name: Build iOS
        run: flutter build ios --release --no-codesign

      - name: Upload iOS build
        uses: actions/upload-artifact@v4
        with:
          name: ios-release
          path: build/ios/iphoneos/Runner.app
```

### GitHub Secrets Setup

Di repository Settings > Secrets and variables > Actions:

| Secret | Deskripsi |
|--------|-----------|
| `KEYSTORE_BASE64` | Keystore file di-encode base64 (`base64 ~/upload-keystore.jks`) |
| `KEYSTORE_PASSWORD` | Password keystore |
| `KEY_PASSWORD` | Password key alias |
| `KEY_ALIAS` | Nama key alias |

### Deploy ke Play Store via GitHub Actions (dengan r0adkll/upload-google-play)

```yaml
# Tambahan job di flutter-ci.yml
deploy-android:
  name: Deploy Android
  needs: test
  runs-on: ubuntu-latest
  if: github.ref == 'refs/heads/main'

  steps:
    - uses: actions/checkout@v4
    - uses: subosito/flutter-action@v2
      with:
        flutter-version: '3.16.x'
    - run: flutter pub get

    # Setup keystore dan build (sama seperti di atas)

    - name: Deploy to Play Store
      uses: r0adkll/upload-google-play@v1
      with:
        serviceAccountJsonPlainText: ${{ secrets.PLAY_STORE_SERVICE_ACCOUNT_JSON }}
        packageName: com.yourcompany.yourapp
        releaseFiles: build/app/outputs/bundle/release/app-release.aab
        track: internal  # Ganti ke production setelah verified
        status: completed
        inAppUpdatePriority: 2
        whatsNewDirectory: release-notes/
```

## Fastlane

Fastlane adalah automation tool untuk iOS dan Android build/deploy.

### Android Fastfile

```ruby
# android/fastlane/Fastfile
default_platform(:android)

platform :android do
  desc "Build and deploy to Google Play Internal Testing"
  lane :beta do
    # Increment build number
    increment_version_code(
      gradle_file_path: "app/build.gradle"
    )

    # Build AAB
    gradle(
      task: "bundle",
      build_type: "Release",
      print_command: true,
      properties: {
        "android.injected.signing.store.file" => ENV["STORE_FILE"],
        "android.injected.signing.store.password" => ENV["STORE_PASSWORD"],
        "android.injected.signing.key.alias" => ENV["KEY_ALIAS"],
        "android.injected.signing.key.password" => ENV["KEY_PASSWORD"],
      }
    )

    # Upload ke Internal Testing
    upload_to_google_play(
      track: "internal",
      release_status: "completed",
      skip_upload_metadata: true,
      skip_upload_images: true,
      skip_upload_screenshots: true,
    )
  end

  desc "Deploy to Google Play Production"
  lane :deploy do
    # Get latest version from changelog
    version = get_current_version_name

    # Build AAB with obfuscation
    gradle(
      task: "bundle",
      build_type: "Release",
    )

    # Upload to Production
    upload_to_google_play(
      track: "production",
      release_status: "completed",
      version_code: version,
    )
  end
end
```

```ruby
      build_number: latest_testflight_build_number + 1
    )

    # Build and archive
    build_app(
      scheme: "Runner",
      export_method: "app-store"
    )

    # Upload to TestFlight
    upload_to_testflight(
      skip_waiting_for_build_processing: true
    )
  end

  desc "Deploy to App Store"
  lane :deploy do
    build_app(
      scheme: "Runner",
      export_method: "app-store"
    )

    upload_to_app_store(
      skip_metadata: true,
      skip_screenshots: true,
      force: true
    )
  end
end
```

## Versioning

### Version Strategy di pubspec.yaml

```yaml
version: 1.2.3+45
#         ^   ^
#         |   +-- versionCode / buildNumber (integer, increment setiap build)
#         +------ versionName (SemVer: major.minor.patch)
```

### Semantic Versioning

| Version | Change | Contoh |
|---------|--------|--------|
| **Major** | Breaking change | 2.0.0 (redesign total) |
| **Minor** | Feature baru, backward compatible | 1.3.0 (tambah filter) |
| **Patch** | Bug fix, performance | 1.2.4 (fix crash login) |

### Automate Version Increment

```dart
// lib/core/config/app_version.dart
import 'package:package_info_plus/package_info_plus.dart';

class AppVersion {
  static Future<AppVersionInfo> getInfo() async {
    final info = await PackageInfo.fromPlatform();
    return AppVersionInfo(
      appName: info.appName,
      packageName: info.packageName,
      version: info.version,
      buildNumber: info.buildNumber,
    );
  }
}

class AppVersionInfo {
  final String appName;
  final String packageName;
  final String version;
  final String buildNumber;

  const AppVersionInfo({
    required this.appName,
    required this.packageName,
    required this.version,
    required this.buildNumber,
  });

  String get displayString => '$version+$buildNumber';
}
```

## Common Mistakes di Deployment

### 1. Lupa Update Version Code

Build gagal di Play Store karena version code sudah ada. Solusi: Otomatiskan dengan Fastlane.

### 2. Keystore Hilang

Keystore hilang = tidak bisa update app. Satu-satunya solusi: buat app baru dengan package name baru.

**Pencegahan:** Backup keystore ke Google Drive / password manager. Gunakan Google Play App Signing.

### 3. iOS Archive Error karena CocoaPods

```bash
# Error umum: "Flutter.podspec" not found
flutter clean
cd ios
pod deintegrate
pod install --repo-update
cd ..
flutter build ios --release
```

### 4. Build Number Tidak Sinkron

Version code di pubspec.yaml, Android build.gradle, dan iOS Info.plist harus sinkron. Fastlane `increment_version_code` otomatis menangani ini.

### 5. Mengabaikan Obfuscation

Tanpa obfuscation, kode Dart bisa di-reverse engineer dengan mudah. Selalu enable:

```bash
flutter build appbundle --release --obfuscate --split-debug-info=build/debug-info
```

**Catatan:** Simpan debug-info file! File ini diperlukan untuk deobfuscate crash stacktrace. Simpan di release artifact.
